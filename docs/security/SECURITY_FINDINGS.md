# GreenPulse Security Findings

## Результаты анализа безопасности

В рамках практической работы был выполнен ручной анализ безопасности и статический анализ Python-кода с использованием Bandit.

## Найденные и потенциальные проблемы

| ID | Описание | Местоположение | Уровень | Решение |
|---|---|---|---|---|
| SEC-01 | Использование subprocess в тестах было потенциально опасным при передаче внешнего ввода | tests/test_greenpulse.py | Низкий | Исправлено: тесты переведены на прямой импорт модулей без subprocess |
| SEC-02 | Авторизация пользователей пока не реализована | future API layer | Средний | При добавлении API реализовать RBAC и проверку прав доступа |
| SEC-03 | Работа с базой данных пока не реализована, но при её добавлении возможен риск SQL-инъекций | future database layer | Высокий | Использовать ORM или параметризованные запросы |
| SEC-04 | Пароли и персональные данные пока не обрабатываются | future auth module | Средний | Хранить пароли только в виде хеша, например bcrypt/argon2 |
| SEC-05 | Отсутствует audit log административных действий | future admin layer | Средний | Логировать операции изменения данных и конфигурации |
| SEC-06 | Нет политики хранения секретов | CI/CD and config | Средний | Использовать GitHub Secrets и не хранить токены в репозитории |
| SEC-07 | Нет rate limiting для будущего API | future API layer | Средний | Добавить лимиты запросов и защиту от злоупотребления API |
| SEC-08 | Не определена политика HTTPS | future deployment layer | Средний | В production использовать только HTTPS и безопасные заголовки |

## Итог

Критических уязвимостей в текущем Python-коде не выявлено. Основные риски относятся к будущим слоям системы: API, база данных, авторизация и production-развертывание.
