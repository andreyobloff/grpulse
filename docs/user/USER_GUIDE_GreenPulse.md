# GreenPulse — руководство пользователя

## Практическая работа №27

Документ описывает порядок работы с прототипом GreenPulse — системой городского мониторинга экологической среды.

GreenPulse предназначен для сбора, проверки и анализа данных экологических датчиков. Система помогает оператору и аналитику контролировать корректность показателей, определять статус качества среды и получать отчеты по станциям мониторинга.

## 1. Назначение системы

GreenPulse используется для:

- приема и обработки данных экологического мониторинга;
- проверки корректности показателей датчиков;
- определения статуса качества среды;
- формирования отчета по станциям;
- ограничения доступа пользователей к данным;
- автоматической проверки качества кода и безопасности через GitHub Actions.

## 2. Целевая аудитория

| Роль | Описание |
|---|---|
| Оператор | Загружает и проверяет данные станций мониторинга |
| Аналитик | Анализирует статусы и отчеты по станциям |
| Администратор | Контролирует доступ пользователей и настройки проекта |
| Разработчик | Поддерживает код, тесты и CI/CD-процессы |

## 4. Регистрация и вход пользователя

В учебном прототипе регистрация реализована на уровне Python-сервиса `AuthService`.

### 4.1. Регистрация

При регистрации пользователь указывает:

- идентификатор пользователя;
- логин;
- пароль;
- роль пользователя.

Пароль не хранится в открытом виде. Для защиты используется хеширование PBKDF2-HMAC-SHA256 с солью.

Пример логики регистрации:

```python
auth_service.register_user(
    user_id="USR-001",
    login="operator",
    password="StrongPass123",
)
```

### 4.2. Авторизация

Для входа пользователь указывает логин и пароль. Если пароль неверный, система отклоняет вход.

```python
auth_service.authenticate(
    login="operator",
    password="StrongPass123",
)
```

## 5. Основной функционал GreenPulse

### 5.1. Загрузка демонстрационных данных

Демонстрационные данные загружаются из модуля:

```text
src/demo_data.py
```

Данные содержат:

- идентификатор станции;
- район;
- тип датчика;
- измеренное значение;
- дату и время измерения.

### 5.2. Валидация данных

Система проверяет:

- пустой идентификатор станции;
- пустой район;
- неизвестный тип датчика;
- значения ниже допустимого диапазона;
- значения выше допустимого диапазона.

Некорректные данные не должны использоваться в расчетах.

### 5.3. Поддерживаемые типы датчиков

| Тип датчика | Назначение |
|---|---|
| pm25 | Контроль мелких твердых частиц PM2.5 |
| pm10 | Контроль твердых частиц PM10 |
| co2 | Контроль уровня CO2 |
| temperature | Температура воздуха |
| humidity | Влажность воздуха |
| noise | Уровень шума |

### 5.4. Статусы качества среды

| Статус | Значение |
|---|---|
| normal | Показатели находятся в допустимых пределах |
| warning | Есть превышение предупредительного уровня |
| critical | Есть критическое превышение |
| invalid | Недостаточно данных или данные некорректны |

### 5.5. Формирование отчета по станциям

Отчет по станции содержит:

- номер станции;
- район;
- количество измерений;
- количество некорректных значений;
- средние значения PM2.5, PM10 и CO2;
- итоговый статус станции.

### 5.6. Контроль доступа к данным

Пользователь с ролью `operator` видит только собственные записи.

Если пользователь пытается получить чужую запись, система возвращает ошибку доступа `403`.

Пользователь с ролью `admin` имеет доступ ко всем записям.

## 7. Частые вопросы

### Как проверить качество данных?

Запустите приложение командой:

```bash
python -m src.greenpulse_app
```

В выводе будет показано количество ошибок и отчет по станциям.

### Что означает статус `critical`?

Статус `critical` означает, что хотя бы один показатель достиг критического порога и требует внимания оператора или администратора.

### Что делать, если данные некорректны?

Проверьте тип датчика, диапазон значения, идентификатор станции и район. Некорректные данные необходимо исправить или исключить из расчета.

### Как проверить безопасность?

Откройте GitHub Actions и проверьте выполнение workflow `GreenPulse Security Scan` и `GreenPulse Security Measures Tests`.

### Как ограничивается доступ к данным?

Каждая запись содержит `owner_user_id`. Обычный пользователь видит только записи, где `owner_user_id` совпадает с его `user_id`.

### Как изменить пароль?

В текущем прототипе отдельная функция смены пароля не реализована. Для production-версии необходимо добавить сценарий смены пароля с повторной аутентификацией и повторным хешированием нового пароля.

## 9. Рекомендации пользователю

- Проверяйте результаты GitHub Actions после каждого изменения.
- Не храните пароли, токены и ключи в репозитории.
- Перед использованием данных смотрите количество ошибок валидации.
- При статусе `critical` проверяйте исходные данные станции и тип датчика.
- Для будущей production-версии необходимо подключить реальную базу данных, API и полноценную систему управления пользователями.
